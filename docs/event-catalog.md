# Общий каталог событий

Каталог объединяет подходящие материалы из всех каналов. Источники — сохранённые оценки и версии материалов в PostgreSQL, включая дочитанный текст статьи при наличии. В выборку входят принятые материалы, дубли и записи с положительной оценкой темы или повторной проверкой. Одна версия материала попадает в общий каталог один раз, даже если её оценили несколько каналов.

## Сопоставление

1. PostgreSQL вычисляет русские словоформы заголовка. Go извлекает известную юрисдикцию, номер законопроекта и явно указанное чтение, принятое или одобренное депутатами. Для этих признаков использует заголовок и до 420 символов начала текста.
2. Каталог сравнивает материал с последними версиями до 500 событий своей области за 72 часа. Совпадение номера документа или URL имеет больший вес, чем пересечение словоформ. Разные распознанные юрисдикции разделяют события при отсутствии общего номера документа. При одинаковом чтении или переходе между чтениями в одной распознанной юрисдикции можно сопоставить разные заголовки по общим словам о предмете закона. Равные лучшие совпадения с разными событиями дают новую карточку.
3. Первый материал создаёт версию 1. Пересказ привязывается к существующей версии. Переход к следующему чтению создаёт новую версию. Запоздавший материал о предыдущем чтении привязывается к сохранённой версии этой стадии, если она известна.

Это первая эвристика. Распознаются только явно перечисленные в коде юрисдикции. Морфология заголовка может пропускать пересказы с сильно разной лексикой. Сейчас версии увеличиваются по обнаруженной стадии чтения. Новые утверждения, для которых такой признак отсутствует, могут быть записаны как пересказ. Векторный поиск и редакционная оценка описаны в [проекте следующей итерации](editorial-architecture.md). [Алгоритм](../backend/internal/news/catalog.go)

## Запуск и повтор архива

Для фонового пополнения задайте `EVENT_CATALOG_SHADOW=1` в `.env` и пересоздайте worker. Фоновый проход пополняет область `shadow` по сохранённым оценкам за последние 72 часа через интервал сбора. Неудачная запись журналируется и повторяется при следующем проходе. Теневой поток пишет только в таблицы каталога.

Для архива смм1 на локальном стенде с ID канала 1 выполните из корня репозитория:

```powershell
docker compose up -d db
docker compose build worker
docker compose run --rm --no-deps worker /app/worker events-replay -date 2026-11-18 -channel 1 -show 185995,191091,193423,222142,224758
```

Команда применяет миграции и читает оценки за указанные московские сутки в порядке исходной оценки. Включение сохранённой положительной повторной оценки проверяет алгоритм сопоставления на более позднем решении редактора и не воспроизводит исторический отбор с точностью до минуты. Параметр `-show` фильтрует только отчёт. Без него отчёт показывает все связи этой области. Нужны материалы локального архива. С пустой базой отчёт будет пустым. Нативный запуск использует `go run ./cmd/worker events-replay` из `backend` и настроенный `DATABASE_URL`.

Контрольный прогон обработал 150 материалов. Каталог создал 105 событий, связал 44 материала как пересказы и зафиксировал одно обновление. Материалы 185995, 191091 и 193423 получили один ID события и версию 1. Материал 222142 открыл событие о вейпах на стадии второго чтения. Материал 224758 получил тот же ID события, версию 2 и отношение `update` для окончательного чтения. При повторном прогоне `new_materials` равнялся нулю. Это результат сопоставления алгоритма. Редакционная проверка остальных групп остаётся отдельной задачей.

Команда использует область `archive/2026-11-18/1` и завершается до запуска сборщиков, планировщика и отправителей. [Таблицы](database.md)
