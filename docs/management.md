# Панель управления и HTTP API

Панель — встроенные в Go HTML, CSS и JavaScript. Браузер загружает её по `/`, а данные получает с того же адреса через `/api/v1`. Обработчики из `internal/httpapi` принимают HTTP-запросы и передают операции в `channels.Service`. Сервис вызывает PostgreSQL, адаптер источника или модель. Управление рассчитано на локальный стенд и работает без аккаунтов.

## Операции панели

| Раздел | Что уходит из формы или браузера | Что происходит дальше |
| --- | --- | --- |
| Источники | Имя, организация, URL, тип, статус, темы и отметка первоисточника | Сервис проверяет URL и сохраняет ресурс в `sources`. Пара `kind + url` уникальна. Отключение задаётся статусом `disabled`. |
| Каналы | Имя, Telegram-получатель, флаг сайта, флаг активности и объект `settings` | Сервис сохраняет назначение и правила в `channels`. Нужна хотя бы одна площадка. Worker читает включённые записи. |
| Пресеты | Имя и объект `settings` | Правила сохраняются в `presets`. Клиент может прочитать объект и передать его при создании или изменении канала. Связь пресета с каналом в базе отсутствует. |
| События | ID канала | API возвращает текущие карточки `events` этого канала. Факты содержат ссылку и организацию, если они известны. |
| Публикации | ID канала | API возвращает записи `publications` всех статусов для этого канала. |
| Согласование | ID публикации и действие `approve` или `reject` | Решение сохраняется для конкретной версии и получателя. Worker читает состояние очереди. |
| Лента сайта | Параметры списка и при необходимости ID канала | API возвращает опубликованные версии сайта. |

У списков параметры `limit` и `offset`. Значение `limit` по умолчанию — 50, максимум — 100. Запрос `PUT` передаёт полное представление редактируемого ресурса. Для JSON-запросов используйте `Content-Type: application/json`.

## Пробный и регулярный сбор

`POST /api/v1/sources/{id}/probe` читает источник из базы и вызывает тот же адаптер, что использует worker. Для `candidate` и `verified` он возвращает до пяти заголовков со ссылкой и датой, если она известна. На пробный запрос отводится до 15 секунд. Пробный сбор сохраняет прежний статус источника, а материалы сразу возвращаются в браузер. Регулярный опрос отдельно сохраняет материалы и обновляет состояние источника. [Сбор материалов](ingestion.md)

## Подбор фильтров через LLM

1. В форме канала или пресета оператор указывает тему, аудиторию и описание того, какие темы исключить.
2. Кнопка **Подобрать фильтры с ИИ** отправляет эти поля в `POST /api/v1/filter-suggestions`.
3. Сервис проверяет ввод. Если модель настроена, он передаёт ей эти три поля и инструкцию вернуть JSON с массивами `keywords` и `blocked_terms` и черновиком `topic_profile`.
4. Сервис проверяет длину, убирает повторы и отклоняет несовместимые списки. Панель заполняет ключевые слова, черновик профиля и, при заданных исключениях, стоп-фразы. При пустых исключениях ручные стоп-фразы формы сохраняются.
5. Оператор проверяет предложения и сохраняет канал или пресет обычной кнопкой. Worker читает сохранённые фразы из PostgreSQL и применяет их при обработке материалов.

Для подключения нужны `LLM_FILTERS_URL` с адресом метода Chat Completions, `LLM_FILTERS_MODEL` и, если провайдер требует авторизацию, `LLM_FILTERS_API_KEY`. Провайдер должен поддерживать JSON-ответы. API возвращает `503` при отсутствии настройки и `502` при ошибке провайдера или невалидном результате. Для оценки новостей worker использует отдельные параметры `TOPIC_LLM_*` и настройку канала. [Код генератора](../backend/internal/channels/filter_llm.go)

## Маршруты

| Метод и путь | Результат |
| --- | --- |
| `GET /api/health` | Процесс API отвечает |
| `GET /api/ready` | PostgreSQL доступна и актуальные миграции применены |
| `GET, POST /api/v1/sources`, `GET, PUT /api/v1/sources/{id}` | Чтение, создание и обновление источников |
| `POST /api/v1/sources/{id}/probe` | Пробный сбор |
| `GET, POST /api/v1/channels`, `GET, PUT /api/v1/channels/{id}` | Чтение, создание и обновление каналов |
| `GET, POST /api/v1/presets`, `GET, PUT /api/v1/presets/{id}` | Чтение, создание и обновление пресетов |
| `POST /api/v1/filter-suggestions` | Предложение фильтров |
| `GET /api/v1/channels/{id}/events` | Карточки канала |
| `GET /api/v1/channels/{id}/publications` | Очередь и история канала |
| `GET /api/v1/review`, `PUT /api/v1/review/{id}` | Очередь и решение по версии |
| `GET /api/v1/site/news` | Лента сайта с необязательным `channel_id` |

Формы запросов и ответов определены в [OpenAPI](../api/openapi.yaml). Значения по умолчанию и порядок запуска описаны в [инструкции по стенду](backend-local.md).

## Проверка темы
Настройки канала и пресета принимают необязательное settings.topic_profile. POST /api/v1/filter-suggestions может вернуть черновик topic_profile.

В строке канала кнопка «LLM и векторы» открывает переключатели. Оба включены по умолчанию. Для работы каждого требуется настроенный провайдер. Выключение сохраняется в профиле явно.
GET /api/v1/channels/{id}/topic-evaluations возвращает историю с limit и offset. POST /api/v1/channels/{id}/topic-evaluations/{materialID}/preview оценивает сохранённый текст по текущему профилю. PUT /api/v1/channels/{id}/topic-evaluations/{materialID}/review сохраняет verdict со значением relevant, irrelevant или insufficient и возвращает 204. В панели функции находятся в «Каналы → Проверка темы». [Подробности](topic-classification.md)
