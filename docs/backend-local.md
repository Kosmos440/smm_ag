# Локальный запуск и диагностика

## Запуск

Из корня репозитория, если `.env` ещё не создан:

```powershell
Copy-Item .env.example .env
```

```powershell
docker compose up --build --wait
Invoke-RestMethod http://127.0.0.1:8180/api/health
Invoke-RestMethod http://127.0.0.1:8180/api/ready
```

Панель открывается на [127.0.0.1:8180](http://127.0.0.1:8180/). API публикуется только на loopback. PostgreSQL доступна сервисам внутри сети Compose. Worker не публикует порт. При корректном запуске `/api/ready` возвращает `{"status":"ready"}`. Новая база после миграций имеет пустые каталог и каналы. В существующем томе сохраняются записи предыдущих запусков.

| Переменная | Кто читает | Назначение |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | Compose и PostgreSQL | Пароль локальной базы. Compose формирует `DATABASE_URL` для API и worker. |
| `SMM_API_PORT` | Compose | Локальный порт API. По умолчанию 8180. |
| `DATABASE_URL` | Go API и worker | Подключение к PostgreSQL. При нативном запуске задаётся явно. |
| `HTTP_ADDR` | Go API | Адрес HTTP-сервера. Нативный запуск использует `127.0.0.1:8180`, Compose слушает внутри контейнера на `0.0.0.0:8180`. |
| `COLLECT_INTERVAL` | Worker | Пауза после сбора. По умолчанию `2m`. |
| `WORKER_TICK_INTERVAL` | Worker | Интервал циклов проверки. По умолчанию `5s`. |
| `TELEGRAM_BOT_TOKEN` | Worker | Токен бота для исходящей доставки. |
| `LLM_FILTERS_URL`, `LLM_FILTERS_MODEL`, `LLM_FILTERS_API_KEY` | Go API | Параметры функции подбора фильтров. Ключ требуется, если его требует провайдер. |

После изменения кода пересоберите соответствующие контейнеры через `docker compose up -d --build api worker`. При правке только параметров запустите `docker compose up -d api` для модели или `docker compose up -d worker` для токена и интервала. Остановка через `docker compose down` сохраняет данные в томе PostgreSQL.

Для запуска без Compose нужны Go согласно [go.mod](../backend/go.mod) и доступная PostgreSQL. Укажите `DATABASE_URL` и запустите `go run ./cmd/api` и `go run ./cmd/worker` в двух терминалах из папки `backend`.

## Первый сквозной сценарий

1. В панели **Источники** добавьте RSS, раздел сайта или публичный Telegram-канал со статусом «Кандидат». Откройте «Пробный сбор», проверьте заголовки, ссылки и даты, затем поставьте статус «Проверен».
2. В **Каналы** создайте включённый канал. Введите тему, аудиторию и нужные ключевые слова. Выберите сайт как площадку для первого теста. При необходимости включите согласование. Параметр возраста задаёт допустимую свежесть, а ожидание в резерве определяет, когда обычный материал сможет выйти.
3. Дождитесь следующего сбора. В **Каналы → События** проверьте карточки, в **Публикации** — статусы. Если версия ожидает согласования, одобрите её в соответствующем разделе.
4. После выпуска проверьте **Ленту сайта** или `GET /api/v1/site/news?channel_id=ID`.

Для отправки в Telegram добавьте своего бота администратором канала с правом публиковать сообщения, задайте токен для worker и укажите в настройках канала имя `@channel` или числовой ID чата. Настройки влияют на следующие циклы, правила доставки описаны в [разделе о публикациях](publishing.md).

## Диагностика

```powershell
docker compose ps
docker compose logs --tail=100 api worker
```

| Симптом | Как проверить |
| --- | --- |
| `/api/ready` возвращает `503` | Проверьте состояние базы, строку подключения и журнал обоих Go-процессов. |
| Пробный сбор возвращает `502` | Проверьте URL и тип источника. Запрос должен завершиться из среды API. Сбой DNS, соединения, TLS, неподдерживаемый ответ и ошибка разбора выглядят одинаково в панели. |
| Пробный сбор успешен, список пуст | Проверьте, отдаёт ли страница нужную разметку, текст и дату. Для одностраничного сайта попробуйте прямую ссылку на статью. |
| Предпросмотр есть, карточек нет | Проверьте статус источника, активность канала, дату, совпадение с темой, стоп-фразы и требование первоисточника. Предпросмотр появляется до оценки. |
| Карточки есть, публикаций на сайте нет | Проверьте площадку, очередь согласования, тихие часы, срок годности и задержку резерва. |
| Telegram показал `failed` или `uncertain` | Проверьте статус, ошибку в истории, токен, chat ID, права и реальное состояние сообщения в канале. [Состояния доставки](publishing.md#состояния-очереди) |
| Подбор фильтров возвращает `503` | Проверьте параметры LLM у API и перечитайте окружение контейнера через его пересоздание. |
| Подбор фильтров возвращает `502` | Проверьте доступ к провайдеру, модель, авторизацию и поддержку JSON-ответов. |

## Проверки

```powershell
docker compose --profile test run --build --rm integration
```

Профиль запускает `go test -count=1 -v ./...` с PostgreSQL. Интеграционные тесты работают во временных схемах и удаляют их после проверки. Они покрывают сохранение материалов и отсутствие дублей, версии событий, согласование, восстановление очереди и выдачу ленты. В сквозном тесте внешняя доставка заменяется тестовой реализацией.

При запуске из `backend` используйте `go test ./...` и `go vet ./...`. Чтобы включить сценарии с БД, задайте `SMM_TEST_DATABASE_URL` с адресом тестовой PostgreSQL. Без этой переменной интеграционные сценарии пропускаются.

## S3 на диске D:

Перед первым запуском создайте каталоги и ключи в .env.

```powershell
New-Item -ItemType Directory -Force D:/smm-agent-media/objects,D:/smm-agent-media/uploads
Add-Content .env ("S3_ACCESS_KEY=" + [Convert]::ToHexString([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32)))
Add-Content .env ("S3_SECRET_KEY=" + [Convert]::ToHexString([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32)))
docker compose up -d --build media api worker
```

Генерация ключей выполняется один раз. SMM_MEDIA_DIR по умолчанию D:/smm-agent-media. S3_BUCKET по умолчанию news-media. Worker использует S3_ENDPOINT=http://media:8333 и MEDIA_TEMP_DIR=/media-upload. S3_ACCESS_KEY и S3_SECRET_KEY обязательны для Compose. Порт S3 наружу не публикуется.

Медиафайлы и временные загрузки находятся на D:. Служебные базы SeaweedFS расположены в Docker-томах media-master, media-filer и media-control, чтобы обойти ошибку rename Windows bind mount. Сохраняйте их вместе с каталогом objects при резервном копировании. Подробности хранения, ограничений и проверки приведены в [media.md](media.md).
