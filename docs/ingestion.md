# Сбор материалов

## Откуда поступают источники

`sources` содержит URL, тип адаптера, организацию, статус проверки и признак первоисточника. Статусы `candidate` и `disabled` служат для подготовки и остановки источника. Worker опрашивает записи со статусом `verified`. Темы источника используются как метки каталога. Список опрашиваемых источников общий для всех включённых каналов. Фильтры каналов применяются после сбора. [Каталог в PostgreSQL](../backend/internal/postgres/catalog.go)

Worker начинает регулярный сбор, если есть хотя бы один включённый канал. По умолчанию пауза между сборами — 2 минуты после окончания предыдущего сбора, а интервал циклов — 5 секунд. Один цикл ждёт завершения сбора, после чего обрабатывает материалы и очередь. До четырёх источников загружаются одновременно. На опрос источника отводится до 25 секунд, HTTP-клиент ограничивает свой запрос 20 секундами. Пробный сбор имеет отдельный предел в 15 секунд. [Планировщик](../backend/cmd/worker/scheduler.go)

## Как загружается ответ

Каталог адаптеров выбирает сборщик по типу `rss`, `website` или `telegram`. Все три используют общий Go HTTP-клиент. Он принимает публичные HTTP(S)-адреса на портах по умолчанию, проверяет IP при установлении соединения и каждый редирект, ограничивает заголовки и тело ответа. Максимальное тело — 4 МиБ. Переход с HTTPS на HTTP отклоняется, прокси из окружения не подхватываются. Адаптеры разбирают ответ только после успешного HTTP `200`. [HTTP-клиент](../backend/internal/ingest/fetch.go)

## Как разбирается каждый тип источника

| Тип | Вход | Извлекаемые данные | Как открывается содержимое |
| --- | --- | --- | --- |
| RSS и Atom | URL RSS, RSS в формате RDF или Atom | Заголовок, URL, GUID или ID, содержимое или описание, дата | XML декодируется с учётом кодировки. Текст берётся из записи ленты, а ссылка на статью сохраняется для просмотра. [Адаптер RSS](../backend/internal/ingest/rss/rss.go) |
| HTML-раздел | URL раздела с карточками | Заголовок из заголовка карточки или ссылки, URL, видимые абзацы и дата | Сборщик ищет `article` и HTML-разметку `NewsArticle`, убирает повторные ссылки и возвращает подходящие датированные карточки. Перехода по ссылкам и запуска JavaScript в этом режиме нет. [Адаптер сайта](../backend/internal/ingest/website/website.go) |
| HTML-статья | Прямая ссылка на публикацию | Название, основной текст, дата, каноническая ссылка или URL открытого ответа | Адаптер распознаёт одиночную статью по структуре и метаданным. Читает JSON-LD, включая `@graph`, и обычные метатеги. Использует текстовое `articleBody` при наличии. Если в JSON-LD указан только блок или текст отсутствует, Readability извлекает читаемую часть HTML. Для коротких материалов остаётся разбор абзацев и описания. [Читалка статьи](../backend/internal/ingest/website/article.go) |
| Telegram | `https://t.me/имя` или `https://t.me/s/имя` | ID сообщения, ссылка на пост, дата, текст, первая содержательная строка как заголовок | Адаптер открывает `https://t.me/s/имя`, находит `data-post`, блок сообщения и `time datetime`. Пропускает записи без текста или даты. Обрабатывает одну публичную страницу предпросмотра, без чтения архива. Ссылки на фото и видео сохраняются вместе с материалом, загрузка выполняется при выпуске через S3. [Медиа](media.md). Токен отправителя для этого не нужен. ## Как результат попадает дальше

1. Адаптер возвращает записи в общем формате `model.Material`. В них входят источник, организация, признак первоисточника, внешний ID, URL, заголовок, тело и дата публикации. Заголовок и тело очищаются от лишних пробелов и ограничиваются 240 и 12 000 символами Unicode соответственно. До 100 материалов возвращаются за опрос источника. При отсутствии внешнего ID используется URL.
2. Worker добавляет `fetched_at` и записывает материалы в PostgreSQL. Сбор хранит возможные версии одной статьи или поста и пропускает повтор той же версии.
3. При успехе worker обновляет `last_success` и очищает `last_error`. При ошибке сохраняет общее сообщение об ошибке загрузки, разбора или записи. Успешный запрос может вернуть пустой набор, например, если разметка страницы не распознана.
4. Для каждого включённого канала worker читает подходящие по возрасту необработанные строки из `materials`. Дальше за них отвечает [обработка новостей](news-pipeline.md).

[Типы и нормализация](../backend/internal/ingest/material.go) · [Запись материалов](../backend/internal/postgres/news.go)

Короткие неоднозначные RSS-материалы worker дочитывает по ссылке в отдельной фоновой очереди. Извлечённое начало помогает определить тему, а полный текст и вложения используются при обработке подходящей новости. [Очередь и условия дочитывания](topic-classification.md)
