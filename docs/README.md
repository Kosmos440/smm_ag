# Документация SMM Agent

Агент опрашивает добавленные RSS-ленты, HTML-страницы и публичные Telegram-каналы. Исходный материал сохраняется в PostgreSQL, а каждый канал публикации отдельно решает, подходит ли ему этот материал. Для принятого события worker готовит отдельные публикации для сайта и Telegram.

| Документ | Что в нём описано |
| --- | --- |
| [Архитектура](architecture.md) | Процессы, внешние системы и маршрут данных от настройки источника до публикации |
| [Структура репозитория](structure.md) | Где читать код каждого компонента |
| [Управление и API](management.md) | Панель, каталог, каналы, пресеты, пробный сбор, согласование и подключение модели |
| [Сбор материалов](ingestion.md) | HTTP-клиент, расписание, адаптеры RSS, сайтов и Telegram |
| [Обработка новостей](news-pipeline.md) | Фильтры, извлечение фактов, карточки событий и приоритет |
| [Публикации](publishing.md) | Резерв, ночное окно, согласование, доставка и обработка сбоев |
| [PostgreSQL](database.md) | Таблицы, связи, транзакции и миграции |
| [Запуск и диагностика](backend-local.md) | Compose, параметры, проверка работы и поиск причин сбоев |

Для первого запуска начните с [инструкции по локальному стенду](backend-local.md). Для изменения логики начните с нужной ветки на [схеме потоков](architecture.md), затем перейдите к владельцу узла по [карте кода](structure.md).

[Медиа и S3](media.md) описывает вложения, хранение на D: и оформление Telegram.
